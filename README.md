# 안경원 고객관리 시스템 - 1단계 MVP

## 포함된 기능
- 상단 버튼바: 고객검색(F6)·신규고객(F5) 작동. 일반판매(F3)/A/S전표/처방전(F11)/AI 고객데이터 분석은 원본과 동일한 위치에 버튼만 배치된 자리표시자(다음 단계 구현 예정)
- 고객 등록/수정, 검색 모달(F6) — 이름/전화번호 뒷자리 검색, 동명이인 목록 확인 후 선택
- 검색 모달에서 고객 선택 시 과거 방문 날짜 목록(초록 박스)이 뜨고, 날짜 클릭 시 그날 검안+매출 기록을 바로 확인 가능
- 신규 검안정보: 안경(굴절) 13항목 + 콘택트렌즈 7항목 (OD/OS), 처방 메모
- 매출정보: 상품 7줄 입력 그리드 (분류/바코드, 브랜드, 상품명, 색상, 수량, 단가) — 수량×단가 입력 시 매출합계 자동 계산
- 결제정보: 현금/카드/상품권 체크박스+금액, 미수, 할인, 현금영수증, 카드구분, 상품권구분, 방문일자/방문주기, 완성일자, 담당자/판매자, 매출메모
- **저장(F10) 버튼 하나로 고객정보 + 검안정보 + 매출/결제까지 한 번에 저장** (이전 버전의 "따로 저장해야 하던" 문제 해결)
- **방문 날짜 불러오기/수정**: 오른쪽 "방문내역" 목록이나 검색 모달의 방문 날짜를 클릭하면 그날의 검안+매출+결제 기록이 화면에 그대로 불려와서 수정할 수 있음. 이 상태에서 저장(F10)을 누르면 새로 만들지 않고 그 기록을 업데이트함
- 검색 모달에서 방문 날짜를 클릭하면 매출정보(상품 목록)와 결제 요약(매출합계/현금/카드/미수/담당자 등)까지 모달 안에서 바로 확인 가능
- 취소(F12): 검안/매출/결제 입력칸만 초기화 (고객정보는 유지)
- 과거 검안정보 이력 조회 (최신순, 좌우 스크롤, 매출합계 포함)
- 방문내역 목록 (오른쪽 패널)

## A/S전표 (수리 접수)
상단 "A/S전표" 버튼으로 열리는 접수 창에서 고객정보 · A/S내역(파손부위/내용) · 비용(선금/잔금/합계)을
입력하고 저장(F10)하면 서버에 저장됩니다. "A/S 목록" 탭에서 고객명/전화번호/고객번호로 검색하고,
접수일자·완성일자 기간으로도 좁혀볼 수 있습니다. 목록에서 행을 클릭하면 그 기록이 전표 화면에 불려와서
수정 후 다시 저장할 수 있습니다. (인쇄 기능은 아직 자리표시자)

## 💾 백업 / 복구 (매장별 + 전체)
헤더의 "⚙️ 설정" → "💾 백업" 탭에서 다룹니다. 모든 매장 계정이 쓸 수 있는 부분과, 관리자만 보이는
부분이 나뉘어 있습니다.

**모든 매장이 쓸 수 있는 "내 매장 백업"**
- "지금 내 매장 백업하기"를 누르면 **이 매장 소유의 데이터만**(고객/검안/매출/반품/미수/A·S) JSON
  파일로 백업됩니다. 다른 매장 데이터는 전혀 섞이지 않습니다.
- 매일 한 번은 자동으로도 백업됩니다(서버가 켜져 있는 동안 1시간마다 확인해서, 마지막 자동백업으로부터
  20시간이 지나면 새로 만듦 — 서버를 매일 재시작 안 해도 하루 한 번은 꼭 돌아갑니다).
- 목록에서 "복구"를 누르면 그 백업 시점으로 **이 매장의 데이터를 통째로 되돌립니다.** 되돌리기 전
  지금 상태도 자동으로 한 번 더 백업해 두므로("복구직전" 표시), 실수로 복구했어도 바로 전 상태로
  다시 되돌릴 수 있습니다.
- 다른 매장은 서로의 백업 파일에 전혀 접근할 수 없습니다(서버에서 매장별로 격리되어 저장/검증됨).

**관리자만 보이는 "전체 관리"**
- 드롭다운에서 매장을 골라 그 매장을 대신 백업/복구할 수 있습니다(매장이 비밀번호를 분실했거나
  직접 조작이 어려울 때 관리자가 대신 처리).
- "전체 시스템 백업"은 **모든 매장의 데이터가 통째로 들어있는 DB 파일 스냅샷**입니다(기존 방식).
  서버 자체가 손상되었을 때 전체를 한 번에 복구하는 재해복구용이고, 매일 한 번 자동으로도 쌓입니다.

**구글드라이브에도 같이 백업하기 (선택사항)**
설정 안 해도 로컬 백업(서버 컴퓨터의 `backups` 폴더)은 항상 정상 동작합니다. 추가로 구글드라이브에도
올려두고 싶으면:
1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고 **Google Drive API**를 사용 설정
2. "서비스 계정"을 만들고 키(JSON)를 다운로드
3. 구글 드라이브에서 백업을 모아둘 폴더를 하나 만들고, 그 폴더를 서비스 계정 이메일(`...@...iam.gserviceaccount.com`)에게 **편집자**로 공유
4. 서버 환경변수 설정 후 재시작:
   ```
   set GDRIVE_SERVICE_ACCOUNT_FILE=C:\경로\gdrive-service-account.json
   set GDRIVE_FOLDER_ID=공유한 폴더의 ID (드라이브 폴더 URL의 마지막 부분)
   ```
5. 설정 → 백업 탭 맨 위에 "☁️ 구글드라이브 연동됨"으로 바뀌면 성공. 이후 모든 백업(매장별+전체,
   수동+자동)이 로컬과 구글드라이브 양쪽에 저장됩니다. 연동이 안 되어 있거나 업로드가 실패해도
   로컬 백업 자체는 항상 그대로 성공합니다(구글드라이브는 어디까지나 "추가 보관"용).

⚠️ 서비스 계정 키 파일(JSON)은 절대 깃허브 등에 올리지 마세요 — `.gitignore`에 흔한 파일명
패턴은 이미 등록해 뒀지만, 다른 이름으로 저장했다면 직접 확인해 주세요.

## 📨 문자 / 카카오 알림톡 보내기
A/S전표 버튼 오른쪽의 "문자/카톡" 버튼을 누르면 보내기 창이 열립니다. 직전에 A/S전표에 고객명·번호를
입력했다면(전표를 닫은 뒤에도) 자동으로 채워져 있습니다. **[알리고(Aligo)](https://smartsms.aligo.in)**
연동으로 동작하며, 서버에 아래 환경변수를 설정해야 실제로 발송됩니다. 설정 전에는 버튼을 눌러도
"아직 연동되지 않았습니다" 안내만 뜨고 실제로 나가지 않습니다(요금 걱정 없이 미리 화면을 써볼 수 있음).

| 환경변수 | 용도 | 어디서 받나요 |
|---|---|---|
| `ALIGO_API_KEY`, `ALIGO_USER_ID` | 알리고 로그인 인증 (전체 매장 공통) | 알리고 가입 후 "API 사용 관리" 메뉴 |
| `ALIGO_SENDER` | 문자 **기본** 발신번호 (매장별 발신번호가 없을 때만 씀) | 알리고에 미리 등록 + 통신사 사전인증 필요 |
| `ALIGO_KAKAO_SENDER_KEY` | 카카오 알림톡 발신프로필 키 (전체 매장 공통) | 카카오 비즈니스 채널을 알리고에 연동한 뒤 발급 |
| `ALIGO_KAKAO_TEMPLATE_CODE` | 승인된 알림톡 템플릿 코드 (전체 매장 공통) | 카카오에 템플릿 심사 신청 → 승인(보통 1~3영업일) |
| `ALIGO_TEST_MODE` | `Y`(기본값, 테스트모드-실제발송 안됨) / `N`(실제발송) | 준비 끝나면 꼭 `N`으로 바꾸기 |

⚠️ **카카오 알림톡은 승인받은 템플릿 문구와 내용이 일치해야 정상 발송됩니다.** 화면에서 자유롭게 입력한
문구를 그대로 보내는 게 아니라, 카카오 심사를 통과한 템플릿의 변수 부분만 채워서 보내는 구조이니
템플릿 승인 시 이 화면에서 쓸 문구 형태를 미리 맞춰서 신청하세요. 문자(SMS)는 그런 제약 없이 자유
문구로 바로 보낼 수 있습니다.

### 매장마다 다른 발신번호로 보내기
알리고 **계정은 하나만** 가입하면 되고(위 환경변수는 서버 전체에 공통 적용), 그 계정에 매장별 전화번호를
발신번호로 각각 등록해두면, **관리자 화면(`/admin`) → 매장 관리 → 수정**에서 매장별로 "문자/카카오
발신번호"를 입력할 수 있습니다. 비워두면 서버 기본 발신번호(`ALIGO_SENDER`)를 그대로 씁니다. 즉,
문자/카톡은 로그인한 매장의 발신번호로 나가고, 발신번호가 따로 등록 안 된 매장만 기본값을 씁니다.

환경변수는 서버를 띄우기 전에 설정합니다 (Windows 명령 프롬프트 예시):
```
set ALIGO_API_KEY=발급받은키
set ALIGO_USER_ID=아이디
set ALIGO_SENDER=0212345678
set ALIGO_TEST_MODE=N
python -m uvicorn main:app --reload
```

## 저장 버그가 고쳐진 이유
이전 버전은 "고객 저장" 버튼과 "검안정보 저장" 버튼이 분리되어 있어서,
고객을 먼저 저장하지 않으면 검안정보가 어느 고객 것인지 연결되지 않아 저장되지 않는 문제가 있었습니다.
지금은 **저장(F10) 버튼 하나가 내부적으로 "고객 저장/수정 → 검안+매출+결제 저장"을 순서대로 함께 처리**하도록 통합했습니다.
홍길동을 새로 입력하고 모든 값을 채운 뒤 저장(F10)을 누르면, 고객 등록과 검안/매출 기록이 한 번에 저장되고
고객검색(F6)으로 다시 불러오면 그대로 조회됩니다.

## 폴더 구조 (중요)
아래 4개 파일이 **같은 폴더 안에** 나란히 있어야 합니다 (하위 폴더 없음):
```
optical_app/
├── main.py
├── database.py
├── index.html
└── requirements.txt
```

## 실행 방법 (Windows)

1. `optical_app` 폴더를 파일 탐색기에서 열고, 주소창을 클릭해 `cmd` 입력 후 Enter (그 폴더 위치에서 명령 프롬프트가 열립니다)

2. 필요한 패키지 설치
   ```
   python -m pip install -r requirements.txt
   ```

3. 서버 실행 (uvicorn 명령이 안 먹히면 python -m uvicorn 으로)
   ```
   python -m uvicorn main:app --reload
   ```
   "Uvicorn running on http://127.0.0.1:8000" 메시지가 뜨면 이 창은 닫지 말고 그대로 두세요.

4. 브라우저에서 아래 주소로 접속 (index.html 파일을 직접 더블클릭하면 안 됩니다)
   ```
   http://localhost:8000
   ```

5. 데이터는 같은 폴더에 `optical.db` 파일로 자동 저장됩니다 (SQLite).
   이 파일을 백업하면 전체 데이터가 백업됩니다.
